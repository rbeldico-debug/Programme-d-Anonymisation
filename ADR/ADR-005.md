# ADR-005 (Révision 2) : Observabilité et Stratégie "Few-Shot"

**Titre** : Renforcement de l'Observabilité (Logs E/S) et Guidage par l'Exemple
**Statut** : Accepté
**Date** : 2025-05-13

**Contexte**
Le passage à un pipeline simplifié (Liste -> Liste) a entraîné des réponses vides ("0 termes"). Le modèle semble échouer silencieusement, soit par blocage de sécurité, soit par incompréhension du format attendu. L'opacité actuelle du pipeline empêche le diagnostic.

**Décision**
1.  **Observabilité Mandataire (Debug Mode)** :
    *   L'argument `--debug` ne doit pas seulement afficher des rectangles colorés sur le PDF.
    *   Il doit **impérativement** afficher dans la console (stdout) :
        *   Le **Prompt exact** envoyé au LLM.
        *   La **Réponse brute** (Raw String) reçue du LLM avant tout parsing.
    *   Cela permet de distinguer une erreur de logique (le code Python coupe mal la réponse) d'une erreur de modèle (le modèle refuse de répondre).

2.  **Stratégie de Prompting "Few-Shot" (Apprentissage par l'exemple)** :
    *   Au lieu de donner uniquement des instructions abstraites ("Liste les noms"), nous intégrerons dans le prompt 2 ou 3 exemples statiques de transformation "Entrée -> Sortie".
    *   *Justification* : Les modèles 20B suivent beaucoup mieux les "patterns" (mimétisme) que les instructions complexes. Si on lui montre un exemple où il extrait une liste, il tendra à reproduire la structure.

**Conséquences**
*   Modification de la signature des méthodes dans `LlmAnalyzer` pour accepter le flag `debug`.
*   Le prompt devient plus verbeux (consomme plus de tokens en entrée) mais garantit une meilleure stabilité.
