### ADR-001 : Architecture de Dé-identification Hybride et Locale

**Date** : 2025-05-12
**Statut** : Accepté

**Contexte**
Le projet vise à anonymiser des comptes-rendus médicaux (PDF) pour permettre leur utilisation en recherche. Les tentatives précédentes basées uniquement sur des modèles d'IA génératifs ont échoué par manque de fiabilité.
Les contraintes sont strictes :
*   **Confidentialité** : Aucun traitement cloud. Tout doit s'exécuter en local.
*   **Précision** : Objectif de suppression des données identifiantes > 99%.
*   **Intégrité** : Pas de perte d'information médicale (ne pas masquer une pathologie par erreur).
*   **Hétérogénéité** : Les formats de documents varient fortement selon les praticiens.

**Décision**
Nous adoptons une architecture de traitement en **pipeline hybride à trois étages**, exécutée localement :

1.  **Moteur de Règles et NER (Microsoft Presidio)** :
    *   Utilisation de la bibliothèque Python `presidio-analyzer`.
    *   Détection déterministe par Regex (Numéros Sécu, Dates, E-mails, Téléphones).
    *   Détection par Entités Nommées (NER) via un modèle Spacy français (`fr_core_news_lg`) pour les noms propres et lieux évidents.
    *   *Justification* : Rapide, gratuit, explicable et couvre 80% des cas triviaux sans hallucination.

2.  **Validation Contextuelle par LLM (Ollama)** :
    *   Les segments de texte contenant des entités potentielles ou ambigües sont soumis à un LLM local.
    *   Le LLM agit comme un "Juge" pour désambiguïser (ex: distinguer "M. Alzheimer" du "Docteur Alzheimer" ou de la "Maladie d'Alzheimer").
    *   *Justification* : Comble les lacunes sémantiques que les règles strictes ne peuvent pas saisir.

3.  **Boucle de Validation Humaine (Optionnelle)** :
    *   Le système est conçu pour le traitement par lots ("Batch processing").
    *   Il génère des métadonnées permettant une révision a posteriori si l'utilisateur le souhaite, mais ne bloque pas le traitement.

**Conséquences**
*   Nécessite l'installation locale de dépendances Python lourdes (Spacy models) et d'un runtime LLM (Ollama).
*   Assure une résilience élevée : si le LLM est lent, Presidio assure quand même le gros du travail.

### ADR-002 : Stratégie de Modèle LLM et Inférence Déterministe

**Date** : 2025-05-12
**Statut** : Accepté

**Contexte**
L'évolution des modèles de langage est rapide. Le projet ne doit pas être couplé fortement à un modèle spécifique qui pourrait devenir obsolète. De plus, l'anonymisation exige une reproductibilité parfaite : le même document doit toujours être anonymisé de la même façon.

**Décision**
1.  **Abstraction du Modèle via Variable d'Environnement** :
    *   Le modèle n'est pas codé en dur. Il est défini par une variable (ex: `ANONYMIZATION_MODEL="gpt-oss:20b"`).
    *   Le code vérifiera la présence du modèle dans le registre local (Ollama) au démarrage.

2.  **Inférence à Température Zéro** :
    *   Les appels au LLM se feront avec une `temperature=0` (ou la valeur la plus basse acceptée par le modèle, ex: 0.1).
    *   *Objectif* : Supprimer la créativité du modèle pour obtenir un comportement quasi-déterministe et binaire (Sensible / Non-Sensible).

3.  **Modèle de Référence** :
    *   Nous ciblons des modèles de classe 7B à 20B paramètres (ex: Llama 3, Mistral, ou équivalents fine-tunés médicaux).
    *   Les modèles plus lourds (>20B) sont écartés pour garantir l'exécution sur des postes de travail standards.

**Conséquences**
*   La qualité de l'anonymisation contextuelle dépendra de la RAM disponible sur la machine de l'utilisateur (pour charger le modèle quantifié).
*   Garantit que le projet reste "State-of-the-Art" sans réécriture de code, simplement en changeant la variable d'environnement vers un modèle plus récent.

### ADR-003 : Préservation du Layout et Masquage Visuel (Blackout)

**Date** : 2025-05-12
**Statut** : Accepté

**Contexte**
La mise en page des comptes-rendus médicaux (positionnement, tableaux, en-têtes) porte une information structurelle importante pour la compréhension clinique (anamnèse). La reconstruction d'un PDF à partir de texte brut est sujette à erreurs et pertes. L'objectif final est la recherche clinique sur le contenu non-identifiant.

**Décision**
1.  **Non-altération de la Structure** :
    *   Le PDF final sera le PDF original modifié, et non un nouveau document généré. La mise en page reste intacte.

2.  **Technique de "Redaction" (Masquage)** :
    *   Les entités identifiées seront remplacées par des rectangles noirs ("Blackout").
    *   Techniquement, le texte sous-jacent sera **supprimé du flux de données** du PDF (et non simplement couvert) pour empêcher le copier-coller ou l'extraction programmatique des données cachées.
    *   Nous utiliserons des bibliothèques robustes de manipulation PDF (ex: `PyMuPDF` ou `pdf_redactor`).

3.  **Absence d'Étiquetage Sémantique** :
    *   Nous ne remplaçons pas le texte par des tags (ex: `[NOM]`). Le masquage est uniforme.
    *   *Justification* : Simplifie la tâche de l'IA (décision binaire : garder/masquer) et focalise la lecture humaine ultérieure sur le contenu médical restant.

**Conséquences**
*   Le document résultant est visuellement "censuré", ce qui est le standard attendu pour la protection des données.
*   Les coordonnées spatiales des mots (bounding boxes) deviennent une donnée critique du pipeline technique.
